🔐 Secrets API Documentation

A full-stack RESTful API learning lab demonstrating the 4 core tiers of API authentication, full CRUD operations (GET, POST, PUT, PATCH, DELETE), dynamic pagination, and credential generation.

💡 Base URL: https://secrets-api-authentication.onrender.com (or http://localhost:4000 locally)
POST /register No Auth Required

Register a new user account. Required before using Basic Auth, API Key, or Bearer Token routes.

Request Body (JSON or Form-Urlencoded):
{
  "username": "developer",
  "password": "securepassword123"
}
Example Response (201 Created):
{
  "message": "User registered successfully! You can now generate an API key at GET /generate-api-key",
  "username": "developer"
}
GET /generate-api-key Basic Auth

Generate a personal API Key using your registered username and password.

Example Request:
GET /generate-api-key?username=developer&password=securepassword123
Example Response (200 OK):
{
  "message": "API key generated successfully!",
  "username": "developer",
  "apiKey": "api-key-k9x2m4p8"
}
GET /get-auth-token Basic Auth

Issues a Bearer Token for authorization on protected secret resources.

Example Request:
GET /get-auth-token?username=developer&password=securepassword123
Example Response (200 OK):
{
  "message": "Bearer Token generated successfully!",
  "username": "developer",
  "token": "bearer-token-9xk3m2p8d7",
  "tokenType": "Bearer"
}
GET /random Level 1: No Auth

Fetch a random secret from the database. Completely public and open to any client.

Live Example:
GET /random
Example Response (200 OK):
{
  "id": 1,
  "secret": "Jack Bauer's favorite programming language is raw binary.",
  "score": 5,
  "username": "jackbauer",
  "timestamp": "2024-01-01"
}
GET /all?page=1 Level 2: Basic Auth

Retrieve all secrets paginated (6 items per page). Requires registered Basic Auth credentials.

Headers:
Authorization: Basic <Base64(username:password)>
Example Response (200 OK):
{
  "pagination": {
    "currentPage": 1,
    "limit": 6,
    "totalItems": 25,
    "totalPages": 5,
    "hasNextPage": true,
    "hasPrevPage": false
  },
  "data": [
    { "id": 1, "secret": "...", "score": 5, "username": "jackbauer" },
    { "id": 2, "secret": "...", "score": 8, "username": "chuck" }
  ]
}
GET /filter?score=7&apiKey=... Level 3: API Key

Filter secrets by minimum score. Requires your active API key passed via query parameter or header (x-api-key).

Example Query:
GET /filter?score=8&apiKey=api-key-k9x2m4p8
Example Response (200 OK):
[
  {
    "id": 2,
    "secret": "Chuck Norris doesn't use APIs; APIs request permission to run on his CPU.",
    "score": 8,
    "username": "chuck"
  }
]
GET /secrets/:id Level 4: Bearer Token

Fetch a single secret by its numeric ID. Requires a valid Bearer Token.

Headers:
Authorization: Bearer bearer-token-9xk3m2p8d7
Example Response (200 OK):
{
  "id": 2,
  "secret": "Chuck Norris doesn't use APIs; APIs request permission to run on his CPU.",
  "score": 8,
  "username": "chuck",
  "timestamp": "2024-01-02"
}
POST /secrets Level 4: Bearer Token

Create a new secret associated with your authenticated user account.

Headers:
Authorization: Bearer bearer-token-9xk3m2p8d7
Request Body (JSON or Form-Urlencoded):
{
  "secret": "I secretly love pineapple on pizza.",
  "score": 9
}
Example Response (201 Created):
{
  "id": 26,
  "secret": "I secretly love pineapple on pizza.",
  "score": 9,
  "username": "developer",
  "timestamp": "2026-10-28T14:00:00.000Z"
}
PUT /secrets/:id Level 4: Bearer Token

Completely replace a secret's fields. Both secret and score must be supplied. Only the user who created the secret is authorized to modify it.

Headers:
Authorization: Bearer bearer-token-9xk3m2p8d7
Request Body (Both fields required):
{
  "secret": "Updated completely new secret message.",
  "score": 10
}
Example Response (200 OK):
{
  "id": 26,
  "secret": "Updated completely new secret message.",
  "score": 10,
  "username": "developer",
  "timestamp": "2026-10-28T14:00:00.000Z"
}
PATCH /secrets/:id Level 4: Bearer Token

Partially update an existing secret. You can supply secret, score, or both. Only the creator of the secret is authorized to update it.

Headers:
Authorization: Bearer bearer-token-9xk3m2p8d7
Request Body (Any subset of fields):
{
  "score": 10
}
Example Response (200 OK):
{
  "id": 26,
  "secret": "I secretly love pineapple on pizza.",
  "score": 10,
  "username": "developer",
  "timestamp": "2026-10-28T14:00:00.000Z"
}
DELETE /secrets/:id Level 4: Bearer Token

Permanently remove a secret from the database. Only the user who created the secret is authorized to delete it.

Headers:
Authorization: Bearer bearer-token-9xk3m2p8d7
Example Response (200 OK):
{
  "message": "Secret deleted successfully",
  "deletedSecret": [
    {
      "id": 26,
      "secret": "I secretly love pineapple on pizza.",
      "score": 9,
      "username": "developer",
      "timestamp": "2026-10-28T14:00:00.000Z"
    }
  ]
}
